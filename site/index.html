Gnosk

Know what your code knows.

local-first open-weight model MIT

Gnosk scans a codebase for personally identifiable information — Aadhaar, PAN, phone numbers, emails, API keys — and writes a redacted data inventory you can hand to a client.

Everything runs on your machine. No file, path, or snippet ever leaves the laptop. You can unplug the network cable and it still works.

Why

Freelancers and small agencies in India are increasingly asked by clients to sign data-protection clauses under the DPDP Act. Enterprise DLP tools cost more than a freelancer's monthly income. Cloud-based scanners require uploading the exact data you're trying to protect.

Gnosk is the local-first alternative: run one command, get a report, keep your files where they are.

Install

# from source (not yet on PyPI)
git clone https://github.com/vinksgoyal/gnosk
cd gnosk
python3 -m venv .venv && source .venv/bin/activate
pip install -e ".[dev]"

# scan a folder
gnosk scan ./my-client-project

# write a client-ready inventory
gnosk report ./my-client-project --output inventory.md

How it works

Deterministic validators first. Aadhaar Verhoeff checksum, PAN format, phone/email patterns, and 12 provider API-key shapes. Fast, auditable, no model needed.

Local model second. Gemma 2B via Ollama reads the surrounding code to separate real customer data from test fixtures. No cloud call. No token bill. No data leaving the machine.

What Gnosk is not

Not a compliance certification. Not legal advice. Not a replacement for a formal audit. It produces a readiness report — a starting point for a conversation with your client or your CA.
